### 💡 How I Work
- **문제 정의부터 시작합니다.** 기능보다 "왜 필요한가"를 먼저 정리하고, 그 답을 도메인 설계로 옮깁니다.
- **데이터 정합성을 타협하지 않습니다.** 재화·잔액처럼 틀리면 안 되는 값은 서버를 기준으로 두고, 동시성 문제를 설계 단계에서 다룹니다.
- **결정은 기록으로 남깁니다.** 설계 결정과 작업 규칙을 문서로 정리해, 누가 합류해도 같은 맥락에서 일할 수 있게 합니다.
- **역할을 명확히 나눠 함께 속도를 냅니다.** 기능 단위(vertical slice)로 담당을 나눠, 서로 막히지 않고 병렬로 개발할 수 있는 구조를 만듭니다.
